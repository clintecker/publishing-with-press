# Fact check: Chapter 2, Installing press

Checked `book/chapters/02-installing-press.md` against `docs/briefs/facts/facts-02.md` (sections 2.1 to 2.3, 12.4, and Shared context sections 1.4, 19, and 20). Line numbers refer to the chapter.

**Captured output.** The `press doctor` capture in the Figure 2.1 art directive (chapter lines 203 to 220) is byte-identical to the fact file (facts lines 110 to 127; checked with `diff`). The fig-alt count, "fifteen lines with a bracketed state", is correct. Examples 2.1, 2.3, 2.4, and 2.5 are commands, not captures. They match the file's commands apart from indentation and line continuation. Example 2.3's third comment is spaced differently from the file (see Drifted 9). Example 2.5's backslash-newlines inside the double-quoted `bash -c` string are valid continuations, so the command is equivalent.

## 1. Unsupported

1. **The doctor's BROKEN state attributed to the epubcheck story.** Line 279: "That distinction is the reason the doctor has a `BROKEN` state." Line 240: "The section 'The toolchain image' later in this chapter tells the story of the program that taught the press this distinction." Searched: BROKEN, binfmt, war story 3, 2.3. The file ties the epubcheck scar to the *verifier*: "a present-but-unrunnable tool is reported as a toolchain fault" (source `verify_formats.py`). It never says that the doctor's BROKEN state came from that scar. Fix: cut the causal claim, or soften it to a parallel: "The verifier draws the same line: a present-but-unrunnable tool 'is reported as a toolchain fault'". Line 240's forward reference then needs rewording to match.
2. **"the first book" provenance.** Line 182: "The press found both facts during its first book". Line 273: "a failure that cost the first book real time". Line 354: "The press met this on its first book." Searched: "first book", "first", war stories 2, 3, and 10. The file never says where these scars came from or what they cost. Fix: soften to the file's framing, "Every production failure earns a mechanical guard and an entry in CLAUDE.md's scars list" (law 4), and cut "cost ... real time".
3. **wrapfig.** Figure 2.3's art directive (line 311) and its published fig-alt (line 312) say the workstation "may lack epubcheck, wrapfig, and lettrine". Searched: wrapfig. It is absent from the file. The writer flags this in report-02. Fix: drop wrapfig. lettrine (texlive-latex-extra) and yinit (texlive-fonts-extra) are supported.
4. **`pip install press` from PyPI.** Line 43: "A plain `pip install press` therefore finds nothing useful." Searched: PyPI, 2.1. The file says only that press is "not published to PyPI". It says nothing about what that command does, and an unrelated PyPI project with that name could install something. Fix: cut, or soften to "A plain `pip install press` does not install this press."
5. **Extras with a Git URL or a clone.** Line 86: "The install documentation spells the command `pip install 'press[tui]'`. Put the `[tui]` after the name `press` in whichever form of the requirement you use, the Git URL or a clone." Searched: tui, extras, INSTALL.md. The file gives install path 3 as `pip install 'press[tui]'` with no source document named, so "The install documentation" is an attribution the file does not make. The file gives no Git-URL or clone form with the extra. For a clone the advice is also wrong, because the extra goes after the path (`.[tui]`), not after the word `press`. Fix: give only the file's wording ("With the desk: `pip install 'press[tui]'`") and note that press is not on PyPI. Better, have the editor confirm a working Git-URL form before printing one.
6. **The shell explanation.** Line 58: "The requirement contains a space and an `@`, and the shell would otherwise split it into pieces". Not in the file. As a technical claim, only the space splits words, because `@` is not special to the shell. Fix: "The requirement contains spaces, so the shell would otherwise split it."
7. **What `CI=false` does.** Line 271: "because a check for a set variable finds the word `false` and counts it as set." The file says only "`CI=false` is truthy" and "not the ambient CI variable" (war story 14). Fix: cut the mechanism and keep "`CI=false` is truthy".
8. **Font-scan behaviour.** Line 345: "a scan of every font the system can see ... the build prints little or nothing". Line 350: "before it sets a single page ... the terminal sits still while the processor works". Line 352: "watch the second attempt sit just as still". The file says only "triggers a several-minute font scan that looks like a hang. It is not a hang." Fix: soften to the file's two sentences, and cut the claim that a restarted build repeats the scan.
9. **Doctor runtime.** Line 367: "The report costs a few seconds". Searched: timings. The file states that build timings are undocumented (20.C). Each BROKEN probe can take up to 15 s. Fix: cut the timing.
10. **Minor glosses not in the file** (low stakes; soften or accept as general knowledge, editor's call):
    - Line 35: "Pillow handles images". The file names Pillow only as a dependency.
    - Line 39: "the right ones to paste into a support request". The file cites SUPPORT.md only for "All three exit 0".
    - Line 86: the desk as "press's full-screen operator console".
    - Line 88: celebrimbor as "the quality framework that gates every press change". The file says "celebrimbor is the quality framework; it is dev/CI only".
    - Line 158: "The MacTeX cask is large, because it carries a full TeX Live distribution". The file's comment says only "lualatex, latexmk, TeX Live".
    - Line 320: "If you want the upscaled result, run that one target on an amd64 machine or in the amd64 image."

## 2. Contradicted

1. **`press doctor && press all` as a readiness gate.** Line 250: "A shell line such as `press doctor && press all` refuses to start a build on a machine that cannot finish it." The file, section 2.3: "**Surprise:** a *broken optional* tool also denies readiness (`doctor.py:46-50`)". Section 20.B.14: "A broken *optional* tool fails doctor." The chapter's own Figure 2.1 disproves the sentence: the only fault on hatter is the optional `claude`, which `press all` does not need, yet the doctor exits 1. On hatter, that shell line would refuse a build the machine can finish. B.14 says not to document this behaviour as a feature, but the chapter may not assert the opposite. Fix: cut the sentence, or reword it to "refuses to start a build unless the doctor reports the machine ready. A broken optional tool, such as `claude` in Figure 2.1, also denies readiness."
2. **What `press all` runs.** Line 338: "Build every edition and run every verifier: `$ press all`". Lines 291 and 293 have "building every edition". The file, 20.B.13: "`press all` builds neither `print` nor `coverwrap`". Section 20.A.10 adds that the known-bad fixtures run in `press check` and `press all`. "Every verifier" therefore overstates what the command runs: print verification is not part of it. Fix: "Build the editions and run their verifiers. The print interior and cover wrap are separate targets."
3. **The "not ready" line.** Line 248: "Otherwise, it begins `not ready:`, names the tools at fault, and repeats the install commands for macOS and for Debian and Ubuntu." The capture reads "not ready: claude (macOS: brew install pandoc mactex-no-gui poppler; Debian/Ubuntu: see the Dockerfile's package list)". For Debian/Ubuntu the line gives a pointer, not commands. The macOS hint also differs from Example 2.3: it has no `--cask` and no epubcheck, so "repeats" is wrong. Fix: "names the tools at fault and gives an install hint for macOS (`brew install pandoc mactex-no-gui poppler`) and, for Debian and Ubuntu, a pointer to the Dockerfile's package list."

## 3. Drifted

1. **Table 2.3 heading "Purpose, as the doctor prints it".** The cells capitalise the doctor's text ("Every build target.") and append the writer's own sentences ("Nothing builds without it."). Line 120 says the table gives "each purpose in the words `press doctor` prints". Fix: set the doctor's words in code or quotes, verbatim and lowercase, and separate them from the gloss. Alternatively, retitle the column "Purpose".
2. **Probe timing.** Line 240: "it allows each attempt 15 seconds". The file says "fails both `--version` and `-v` within 15 s". The file does not say whether the limit is per attempt or total, or that `-v` runs only after `--version` fails. Fix: use the file's wording.
3. **Real-ESRGAN on arm64.** Line 320: "On arm64, `press art enhance` resamples a plate instead of upscaling it." The file scopes this to the image: "The arm64 image has no upstream Real-ESRGAN binary, so `art enhance` there resamples". The macOS capture itself shows `realesrgan` as `ok`. Fix: "In the arm64 image, `press art enhance` resamples ...".
4. **"For a tool that failed, the purpose begins with the reason"** (line 226). The file shows this only for BROKEN. No MISSING line is captured. Fix: "For a broken tool, ...".
5. **Table 2.4, `absent`:** "with the reduced behavior noted on its line". Only epubcheck's purpose notes a reduced behaviour, and claude's does not. Fix: cut the clause, or say "for epubcheck, the line notes the reduced behaviour".
6. **The grep warning** (line 253) drops the scar's scope. The file has "Never pipe a check command into grep before `&&` *in a commit chain*". The generalisation is sound, but the phrase "now a scar" points at the exact text. Fix: restore "in a commit chain", or remove the implication that this is the scar's wording.
7. **The API keys** (line 242): "Neither key matters until you commission art". The file shows `press cover` also calling gpt-image-2 (20.A.16), so the OpenAI key matters for covers too. Fix: "until you generate art (Chapter 11)".
8. **"It adds four things"** (line 264). The file's 20.B.19 also records that the Dockerfile installs PyYAML and unpinned Pillow. "Four things" reads as exhaustive. Fix: "It adds, among other things, ...". B.19 is a bug-like item, so do not describe it as a feature.
9. **Example 2.3, third line.** The comment spacing is collapsed: the file has `brew install epubcheck              # optional: ...`, aligned with the line above. The example is presented as the install guide's commands "with their comments". Fix: restore the alignment.
10. **Apple Silicon and the install guide** (line 316): "the Homebrew route in Example 2.3 is the one the install guide gives for it". The file says the guide gives it for macOS, not specifically for Apple Silicon. Fix: "the macOS route in Example 2.3 serves it".
11. **"A red result means one verifier refused an artifact"** (line 362). A red `press all` can also come from a check or a known-bad fixture (20.A.10). Fix: "means a check or verifier refused".
12. **"Both roads start at the same tag"** (line 107). This holds only when the local install pins the same tag. An editable clone does not. Fix: "both can start at the same tag".
13. **Footnote `[^macos]`:** "it cancelled every job there within a second". The file has "cancelled within a second" and does not say "every job". Fix: drop "every job".

## 4. Missing

1. **`pdfimages`** (facts 2.2, "Not checked by doctor, but used"): "Its absence softens two checks to notes." Line 141 lists the programs the doctor does not report (java, oxipng/pngcrush, Chrome) but omits the one a book actually uses. A reader with a partial poppler install would get quietly softened checks and a clean doctor report. State it as fact, not as a feature (B.14).
2. **The broken-optional readiness rule** (facts 2.3, "Surprise"). Without it the reader cannot see why Figure 2.1 says "not ready: claude" when `claude` is optional. This is the fix for Contradicted 1.
3. **The `warn` state** (facts 2.3). It is listed but undefined. The writer deliberately left it out of Table 2.4, which is acceptable because the table says "most often". Severity may.
4. **Matching CI exactly.** Line 307 tells the reader to swap `:latest` for the digest. CI also installs press from the action's own checkout at the pinned ref (facts 2.1 path 6). A local build that installs `@v3` may therefore still differ from CI. Severity may. Add "and install the same three-part tag".
