# Fact check: Chapter 9, The house design

I checked `book/chapters/09-the-house-design.md` against `docs/briefs/facts/facts-09.md`. That covers sections 7.1 to 7.5, 4.5, and 4.4, and the Shared context (1.4, 19, 20). Line numbers refer to the chapter.

**Captured output.** The chapter has no captured output. Its two code blocks, Examples 9.1 and 9.2, are configuration files. The captions present both as the Alice example's real files. The fact file has neither of them (Unsupported 1 and 2).

**The large-print contradiction.** Section 7.2 says large print "sets a larger base face", and in the next sentence it says "Every profile's font size stays 10pt; only the leading changes." The first is a quotation from `docs/PRINT-FORMATS.md`. The second agrees with the profile table, which changes only indent, leading, and the Web measures. By rule 20.A, the code wins. The chapter took the code's line and said it plainly. Line 156 nearly repeats the file: "The PDF body stays at 10 points in every profile, and only the leading changes." It also limits the claim to the PDF, which is correct, and it does not quote "larger base face". That is the right choice. One part of the doc's phrase does have support in the profile table: large print's Web type is 1.4rem against the house 1.25rem. Table 9.4 gives that value, but the prose that explains why large print earns its name leaves it out (Missing 2). Table 9.2 says "Every profile keeps this size". That is acceptable because Table 9.2 is a PDF table.

**Section 20 items.** The chapter handles all the items that apply here. hypcap (A.4): correct, with a footnote saying the package was removed. The 6.3in cap (A.5): the chapter says "set by each profile" and gives the per-profile caps. Print side margins (B.1): stated for the house page only, and the chapter does not claim that other profiles keep their own print margins. The landing page's trim text (B.3): the chapter quotes the PDF row without `{trim}`. `raised-cap` (B.7) and the fixed `lang="en"` (B.8): neither is mentioned, and the chapter says correctly that the reader takes `lang` from metadata. txt/docx (B.10): not mentioned.

## 1. Unsupported

1. **Example 9.1 presented as the Alice example's file.** Line 275: "**Example 9.1. The design part of the Alice example's aesthetic.yaml**", followed by a red palette, a `web-family` stack, and `book-colors`. Line 273: "Example 9.1 gives the Alice example a red cloth". I searched for Alice, aesthetic, cloth, and 7b2d26. The fact file has no Alice aesthetic. The writer's report says the value syntax (quoted `"#rrggbb"`) comes from this book's own `config/aesthetic.yaml`. The caption makes the file sound real, so a reader will look for it in the example. Fix: recast it as a sketch ("**Example 9.1. A red cloth for the Alice example**", and "Example 9.1 shows how the Alice example could take a red cloth"). Otherwise, have the editor print the real file.
2. **Example 9.2 and the claim that Alice "needs" it.** Line 328: "The Alice example needs one change of a different kind. Its plates are alpha masters, black ink on transparency, and in the dark theme they sit on the dark `--paper-warm` mat. Example 9.2 gives them a light panel in the dark theme only." Line 330: "**Example 9.2. The Alice example's extra.css**". The file says nothing about an Alice `extra.css`. The only example `extra.css` it describes is the chapbook's (`.reader main {max-width: 30rem}`, line-height 1.85). The writer's report says the pattern comes from this book's own `assets/web/extra.css`. The report also says the writer framed the panel "as the Alice author's choice, not as a fix". The prose does the opposite: "needs" frames it as a fix. That puts the chapter against Chapter 5's statement that an alpha-master plate "reads on a light page or a dark one". Fix: "An author who wants the plates on a light panel in the dark theme can add a rule like the one in Example 9.2", with the caption "**Example 9.2. A dark-theme plate panel in extra.css**". Cut "needs".
3. **The Alice running heads.** Line 125: "In the Alice example, a page in the middle of the first chapter carries *Alice's Adventures in Wonderland* at its inner head. Its outer head reads "Down the rabbit-hole", and its folio sits in the centre of its foot." I searched for Alice, rabbit, and the title. The file gives neither the example's title nor its chapter titles, and it does not show a rendered running head. Fix: describe the mechanism only ("the inner head carries the book title and the outer head the chapter title"), or have the editor confirm both strings against a build.
4. **The contents page "through the A-heads of each chapter".** Line 61: "The contents page goes one level deep, through the A-heads of each chapter." The file gives only "`toc-depth: 1`; 'Contents'", and the scar says that "`toc-depth: 1` sets tocdepth 0". In `scrbook`, tocdepth 0 is the chapter level, so the contents page probably lists chapters and no A-heads. Contradicted 1 covers this. It is listed here too because the file never says the A-heads appear.
5. **The purpose of the figure-cap gap.** Line 45: "On the house page the cap stands 1.2 inches short of the text block, which leaves room for a caption under the tallest figure." The arithmetic (7.5 - 6.3) is sound. The file does not give the reason. War story 1 says only that the fix "caps every image at 6.3in (now per profile)". Fix: "On the house page the cap stands 1.2 inches short of the text block." Cut the purpose clause, or have the editor confirm it.
6. **Web palette syntax.** Line 308: "A Web palette value is a CSS color, so it keeps its `#`." The file says only that `book-colors` are "given as hex without `#`". It gives no syntax for `web-palette` values, and the writer's report says the quoted `#rrggbb` comes from this book's config. Fix: have the editor confirm it against the press's `aesthetic-house.yaml` or the book-aesthetics skill, or cut the sentence and keep only the `book-colors` rule.
7. **What a left-out field falls back to.** Tip, line 317: "The fields you leave out do not fall back to the house values." The file says only: "The merge is a **top-level replace**: 'restate a whole section when you touch it'." It does not say what the sheet does with a token that the book's palette leaves out. The substitution replaces named tokens in `reader.css`, and the sheet has its own values. The writer's report lists this as unknown ("What happens to unnamed palette tokens after a top-level replace. Not stated"). The tip states it anyway. Fix: "When you change one field of an aesthetic section, copy the whole section into your file first and edit the copy: the merge replaces the section as a whole." Line 314's "Nothing from the house section survives inside it" is a fair reading of "top-level replace" and can stay.
8. **The replacement-sheet warning.** Line 342: "Press no longer adds the profile's Web measure, and an unset width runs the lines across the whole screen." The file: "The profile web measure is not appended." It says nothing about what happens when the width is unset. "No longer" also suggests that press once appended the measure to a replacement sheet, and the file does not say that. Fix: "Press does not add the profile's Web measure to a replacement sheet, so your sheet must set the width of the leaf."
9. **Where a book names its profile.** Line 135: "A book names one in its metadata, as Chapter 3, *The shape of a book repository*, describes." The file does not name the key or the file that selects a profile. Section 4.5 mentions only "metadata `chapter-opening` ... merged over the design profile's default". 10. **The aesthetic's art direction for the logomark and the portrait.** Line 256: "It holds the art direction for the cover, the plates, the logomark, and the portrait". Section 7.4 names only `cover.style` and `plates.style`. Fix: "It holds the art direction for the cover and the plates, among others, which Chapter 11 describes", or confirm the rest against Chapter 11's fact file.
11. **Low-stakes glosses not in the file.** The editor can soften these or accept them as general knowledge:
    - Line 63: "The first book found a scar here." The file gives the scar (war story 4) but does not say where it came from.
    - Line 49: "where the binding takes up paper". The file says only "shifted toward the gutter".
    - Sidebar, line 54: "Neither mistake raises an error, and a printer bills for every page." The file says openany is "silently ignored". It does not say that `open=right` fails without an error, and it says nothing about billing.

## 2. Contradicted

1. **Contents depth.** Line 61: "The contents page goes one level deep, through the A-heads of each chapter." File 7.1 and war story 4: "`toc-depth: 1` sets tocdepth 0", the scar that "silently empties the List of Plates". Depth 0 in `scrbook` is the chapter level. One level deep means chapter titles, not the A-heads inside them. The chapter's own next paragraph says the same thing ("a shallow contents page"). Fix: "The contents page goes one level deep: it lists the chapters." If the editor believes the A-heads do appear, a build must settle it before print.
2. **"Every token of the light palette".** Line 314: "Example 9.1 follows it, and it writes out every token of the light palette, including the ones it keeps." File 7.4 lists twelve tokens: "paper, paper-warm, ink, ink-soft, cloth, cloth-deep, foil, foil-bright, foil-deep, hairline, link, ornament". Line 271 repeats the twelve. Example 9.1's `web-palette` writes ten. It leaves out `hairline` and `ornament`. Fix: add `hairline` and `ornament` to Example 9.1, or change line 314 to "it writes out the light palette's base colors, including the ones it keeps."
3. **"The same red".** Line 273: "moves the PDF accent and links to the same red." Example 9.1 gives `accent: "7B2D26"` and `link: "5C1F1A"`, which are two different reds. Line 308 then calls the link "the dark red". The chapter disagrees with its own example. Fix: "moves the PDF accent to the cloth red and the links to the deep cloth red."

## 3. Drifted

1. **`book-colors` overrides four colors, not six.** Line 98: "The house PDF uses six named colors, and the aesthetic can override them through `book-colors`." File 7.4: "`book-colors.{ink,muted,accent,link}`". Table 9.7 has it right. Fix: "The house PDF uses six named colors. The aesthetic can override four of them through `book-colors` (Table 9.7)."
2. **"In either list".** Line 65: "The last option sends a link in either list to the top of the picture". The file supports this only for the list of plates ("list-of-plates links overshoot the image", war story 5). Fix: "sends a link in the List of plates to the top of the picture", or confirm that the `.lof2` list shares the fix.
3. **Issue 262.** Footnote, line 363: "The correction was issue 262 in the press's tracker." The file gives "Fixed in 3.0.1 (#262)" and does not say whether 262 is an issue or a pull request. Fix: "The correction was number 262 in the press's tracker."
4. **Placements the file does not give.** Line 192: the "Chapter N" line sits "above" the `h1` and the diamond rule "below it". The file says only "with a small-caps 'Chapter N' line and a diamond rule". Line 198: the previous and next links "sit below the masthead". The file gives "←/→ links" with no position. Line 194: tables become cards "one per row". The file says only "tables become cards below 34rem". These are probably right. The editor should confirm them against the screenshot for Figure 9.3 when it exists.
5. **Drawer wording.** Line 198: the drawer "lists every chapter and opens with the current chapter expanded." The file: "a `<details>` contents drawer with the current chapter expanded." "Opens with" can be read to mean that the drawer starts open, and Figure 9.3's art note shows it closed. Fix: "lists the chapters, with the current one expanded."

## 4. Missing

1. **Drop caps are off by default.** Section 4.5: `chapter-opening` is "merged over the design profile's default, which is `none` in every shipped profile." The chapter describes the PDF drop cap (line 117) and the reader drop cap (line 194), and Figure 9.3 shows one. It never says that the house design sets no drop cap until a book asks for one. A reader will expect drop caps on a default build. Add a clause at line 117: "No shipped profile turns this on. A book asks for it, as Chapter 4 shows."
2. **Large print's larger Web type.** Line 156 says large print earns its name through "its page and its spacing". Table 9.4 also gives it the largest Web type (1.4rem against the house 1.25rem). That is the one place where the file supports "a larger base face". Add "and, on the Web, 1.4rem type."
3. **The landing page's JSON-LD.** Line 212 gives the chapter page's `Article`. It leaves out the file's other half: "The landing page is a `Book` with `workExample` entries for the shipped editions."
4. **The `scene-break` default.** Table 9.7 lists `rule`, `asterism`, and `fairy-dust`. It does not say that `rule` is the default (4.4), or that txt and docx keep a plain rule either way.
