# Fact check: Chapter 6, Checking the manuscript

I checked `book/chapters/06-checking-the-manuscript.md` against `docs/briefs/facts/facts-06.md` only: sections 6.4, 6.5, 6.6, 4.9, 4.1, and 3.3, plus the Shared context (1.4, 19, 20). Line numbers refer to the chapter.

**Captured output.** The one captured session is Example 6.12 (and its twin, the art directive at line 454). Facts-06 does not hold that capture. Section 6.5 says "The success output is quoted in §3.4", and §3.4 is not in this file, so I could not check it character for character (see Unsupported 1). Example 6.13 is presented as a session (`$ press check`) but is built from the writer's own observation, not a capture in the file (Unsupported 9). Every other message the chapter quotes as a template matches the file's wording: `missing source file` (described), `unfinished marker '<phrase>'`, `metadata missing <key>:`, `sentinel not found in the manuscript: <s>`, `Source checks passed: N ordered Markdown files`, `Editorial checks passed: N Markdown files`, `Editorial warnings:`, `Jargon check passed: no rewrite-status terms (full audit in build/jargon-report.txt)`, the three self-test failures, `glyph U+XXXX is outside the print-font set`, `manual number in heading`, `title-case heading:`, `paragraph N has W words (the law is under 190; split it)`, `<file>:<line>: <label>`, the malformed-regex refusal, the jargon sighting form, and the release refusal. Examples 6.2, 6.9, and 6.11 fold those messages without saying so (Drifted 4). Example 6.6 matches the file's three watchlist rows character for character apart from disclosed folding. Example 6.5 matches the 14 rewrite terms. The template quotation at line 401 and the scars quotation at line 519 are verbatim.

## 1. Unsupported

1. **Example 6.12 and the self-test summary line are not in this file, and they contradict the chapter's own account of the Alice example.** Line 114 quotes `Checker self-test passed: 19 known-bad fixtures each tripped their declared rule, known-good fixture accepted, 2 extra diagnostics noted`, and line 433 presents Example 6.12 as "the whole output for the Alice example on `hatter`". I searched for "Checker self-test passed", "also drew", and "extra diagnostics". The file gives only the note form (`note: <fixture> also drew: …`) and points to §3.4 for the success output. Worse, the capture cannot be the Alice example's as the chapter describes that example:
   - The chapter gives Alice its own known-bad fixture (Example 6.1) and says "A book with its own fixtures shows a larger count" (line 114), yet the capture reads 19.
   - It reads `Source checks passed: 1 ordered Markdown files`, but Alice has at least `book/chapters/01-down-the-rabbit-hole.md` (Example 6.13), and line 68 says 1 is what "a fresh scaffold prints ... for the preface alone".
   - It reads `Editorial checks passed: 1 Markdown files`, but line 235 says the count includes the audit directories, and Alice names `appendices` (Example 6.8, line 378).
   - The explanation at line 452 ("the em dash is also outside the glyph law's ranges, so the fixture draws both") predicts a third note: curly quotes (U+2018 to U+201D) are also outside the glyph ranges, so `curly-quotes.md` should draw one too, yet the capture shows two.

   This looks like a fresh `demo` scaffold's output with the slug changed. Fix: have the editor confirm against §3.4's capture. If §3.4 is the scaffold's output, present Example 6.12 and Figure 6.3 as "a passing check on a freshly scaffolded book", not as the Alice example. Otherwise rerun it on the real Alice example and capture that. Either way, cut or hedge "so the fixture draws both" until the editor can account for `curly-quotes.md`.
2. **The Alice example's description.** Line 53: "The Alice example sets it to 'A girl falls down a rabbit hole.' and passes." I searched for Alice and for the description. Nothing. Fix: cut the sentence, or have the editor confirm it against the example's `config/metadata.yaml`.
3. **Unfinished markers inside examples.** Line 51: "the checker reads examples for them too". The file lists the markers and says nothing about fenced code for this check. The writer observed it while drafting (report-06). Fix: have the editor confirm. Otherwise soften to "This chapter does not show the three markers, because the checker would refuse them."
4. **What the figure-placement check refuses.** Line 62: "Press refuses an unknown placement, an absolute width, and the `left` and `right` placements." The file says only "Figure placement errors" (6.4). 20.A.11 mentions that a measure on a non-in-flow place or on a plate is refused, which is not the list given. Fix: "Press refuses a figure whose placement is not valid. Chapter 9 describes the placements." Or the file's wording: "Figure placement errors".
5. **What the source-check count counts.** Line 68: "with the count of chapter and appendix files" and "A fresh scaffold prints 1, for the preface alone." The file gives only `Source checks passed: N ordered Markdown files`. I searched for preface and scaffold chapter. Fix: "with the number of manuscript files it read, in order". Cut the scaffold sentence unless the editor confirms it from §3.4.
6. **Book banned patterns apply to the packaged fixtures.** Line 148: "Your banned patterns also apply to the packaged fixtures, since press judges those as book prose too." The file says that *book* fixtures "are judged as book prose under the book's own banned patterns" (6.5). It says nothing about the packaged ones. The writer observed it in this repository (report-06). The follow-on, "A note count that rises after you add a rule means your rule overlaps a house rule", is inference. It actually means the rule matches text in a packaged fixture. Fix: have the editor confirm. Otherwise cut the paragraph.
7. **What counts as one paragraph.** Line 229: "A tip, a warning, or a sidebar is one paragraph to the checker ... A figure's `art:` comment and its image line together are one paragraph as well." I searched for paragraph, block, sidebar, and art comment. The file gives the 190-word law and the message, nothing about how blocks are counted. Fix: cut the three sentences after "counts from the top of the file", or have the editor confirm them.
8. **The editorial count includes the audit directories.** Line 235: "The count covers every file the audit read, the audit directories included." The file gives only `Editorial checks passed: N Markdown files`. Fix: cut the sentence. (It also conflicts with Example 6.12; see 1.)
9. **The failure output's form.** Line 459: "The style audit's header is `Editorial checks failed:`, and each diagnostic below it begins with a hyphen, the filename, and a colon." The writer observed this in the book's own check (report-06). Fix: have the editor confirm against a captured failure. 10. **What `allow` and `ban` do.** Table 6.5: `allow`, "The lint reports nothing", and `ban`, "The lint refuses the term at every threshold except `none`". 11. **The generated fixture map.** Line 142: "your own fixtures need no entry in it." Footnote `[^generated]`: "a file in the press's own repository. The file says only that `expected.yaml` is "Generated from quality/fixtures.yaml". 20.A.3 warns that other `quality/` paths in the docs are stale (the real ledgers live in `.celebrimbor/`), so even the existence of that file is unconfirmed. Fix: footnote, "The file's header says it is 'Generated from quality/fixtures.yaml'." Cut "and your own fixtures need no entry in it", or keep it as "Your own fixtures declare their rule with an expect comment instead."
12. **Regex details.** Line 353: "begin it with the inline flag `(?i)`". Line 357: "Press compiles every pattern before it reads a chapter". The file says the patterns are "case-sensitive regexes, as written" and that a malformed one is refused. 13. **The Alice example's house rules.** Line 328, Example 6.8 ("the house rules of the Alice example") and line 378 ("The Alice example names *appendices*"). 14. **The sidebar's narration of the incident.** Line 521: "The checker failed and said so, in plain text, on the terminal. Grep read that text, found the line it looked for, and exited 0 ... 15. **The exit codes.** Line 494: "`press check` exits with status 0 ... exits with a nonzero status". Facts-06 gives no exit code for `press check`. The writer cites facts-01 for 0. War story 11 implies a red check has a failing status. This is low risk. Fix: have the editor confirm the 0 from facts-01. "Nonzero" is safe.
16. **`press all` runs the check before any build.** Line 496: "`press all` runs the checker before it builds any edition, so a manuscript that fails the check never reaches pandoc." 20.A.10 says the fixtures run in `press check` and `press all`. 17. **Glosses with no source.** These are low stakes. Soften them, or let the editor accept them as framing.
    - Line 34: the rationale for the pass order ("prose is the part of the book that changes most often"). The file gives the order, not the reason.

## 2. Contradicted

1. **"Every book ... passes through one command first" and "none of it exists until all four passes succeed."** Line 17: "Every book that press builds passes through one command first. That command is `press check` ... refuses to let them reach the typesetter." Line 36: "Everything to the right is an edition, and none of it exists until all four passes succeed." Figure 6.1 draws the only road to `press pdf`, `press epub`, and `press site` through the four boxes. 20.A.10: "The fixtures run in `press check` and `press all`, not in a bare `press pdf`." So a bare `press pdf` builds an edition without the second pass, and the file never says that it runs the other passes either. The chapter itself says so at line 154. Fix: line 17, "Before a book goes to press, it passes through one command. That command is `press check` ..." Line 36, "`press all` runs the check alongside the builds. A bare format target such as `press pdf` does not run the self-test." Figure 6.1: draw `press all` (or "release build") on the right, not the three bare targets, or caption it "as `press all` runs it".
2. **The dependency edges and a stale edition.** Line 496: "the same edges keep a verifier from blessing an edition that the current manuscript did not produce." War story 8 supports the edges, but 20.B.11 says: "`press verify-formats` includes an existing, possibly stale, `dist/<slug>.pdf` in the cross-edition agreement check without rebuilding it." Fix: "and the same edges exist so that a verifier rebuilds an edition before it checks it." Do not claim the guarantee is complete.
3. **Curled quotes "in every edition."** Line 209: "pandoc's smart typography curls your straight quotes in every edition." 20.B.9: "The Markdown edition is raw stitched source." The Markdown edition keeps straight quotes. Fix: "curls your straight quotes in the typeset editions".

## 3. Drifted

1. **The drop-cap warning is unconditional.** Warning at line 404 and line 407: "The drop cap splits and small-caps a chapter's opening word". Section 3.3 gives `chapter-opening.style` as "the profile's (house: `none`)". A house-profile book has no drop cap unless it sets one. Fix: "If your book sets a drop cap, do not choose a sentinel from the first words of a chapter ..." and, at line 407, "In a book with a drop cap, a sentinel at the head of a chapter passes the checker".
2. **"Any word in capitals."** Line 221: "Press sets aside the heading's first word, a list of 21 small words, and any word in capitals." The file says "ALL-CAPS words". "In capitals" can read as "capitalized", which would empty the test. Fix: "and any word in all capitals".
3. **"A fully capitalized heading."** Table 6.3, `title-case.md`: "holds a fully capitalized heading". The fixture is `# A Heading That Is Fully Title Cased Everywhere`, which is title case, not all capitals. All-capitals words are exempt from the test (4.1). Fix: "holds a heading in title case".
4. **Folded messages not marked as folded.** Examples 6.2, 6.9, and 6.11 break the file's one-line messages and indent the continuation with four spaces. Examples 6.6 and 6.12 say they are folded; these three do not. A reader who greps for the message, or copies it, gets the wrong text. Fix: add "folded to fit the page" to each lead-in, as at line 300.
5. **"190 words or more."** Table 6.7, `paragraph N has W words`: "A paragraph has 190 words or more." The file says "must be under 190 words" and "Over 190 gives an error" (4.1), so exactly 190 is ambiguous in the file. Fix: "A paragraph is not under 190 words", matching the message's own "the law is under 190".
6. **"Each fixture holds one fault" and "most of them declare."** Line 74. `jargon.md` holds three rewrite terms, as Table 6.3 says at line 128 ("The seam is load-bearing and the blast radius is clean."). All 19 packaged fixtures declare an expected rule (6.5 table). Fix: "Each fixture targets one rule, and every packaged fixture declares which rule must catch it."
7. **"On every run."** Line 146: "A fixture is the only way to show, on every run, that a pattern ... still catches". 20.A.10: the fixtures run only in `press check` and `press all`. Line 154 says so. Fix: "on every check".
8. **Retail refusal.** Table 6.2: "it refuses a retail book that still holds a placeholder." Section 3.3: "`true` makes missing or pending numbers fail `check`." Fix: "it refuses a retail book with a missing or pending number."
9. **Attribution of the maxim.** Line 72: "The press's own documentation puts it plainly". The file quotes "A rule that cannot fail is not a rule." in 6.5 without naming its source document. Fix: "The press puts it plainly".
10. **Trailing whitespace "space or a tab."** Table 6.4 and the last row of Example 6.3. The file's rule is "trailing whitespace". Tab is a reasonable reading, but Example 6.3 is introduced as "the patterns themselves, as the press matches them". Fix: write the row as `(whitespace at the end of a line)`.

## 4. Missing

1. **Two hyphens are not refused.** Section 4.1: "Writing `--` in source is not banned by the checker, but the house law says 'rewrite the sentence instead'." A reader who learns from Table 6.4 that the dash characters are refused will reach for `--`, which pandoc turns into an en dash. One sentence after line 205, or in the dash rows, would close the gap.

The file supports this (4.1: "Prose rules skip fenced code, except the trailing-whitespace rule"). But the writer reports observing banned patterns firing inside fenced code (report-06, Deviations, on `leverage`). If that observation holds, line 205 is wrong for book banned patterns. "Might choose" hedges this, but pick phrases the example actually contains.

The chapter puts it on the first line, above a heading. Both forms are valid under the first-match rule. This is not an error.
