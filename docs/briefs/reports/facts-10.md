## 2. Contradicted

1. **The `mock turtle` example misstates the boundary rule.** Line 283: "The string `mock turtle` also misses 'mock-turtle', because the hyphen counts as part of a word." The file gives the boundary as `(?<![\w-])…(?![\w-])`, which tests only the character *before* and *after* the match. `mock turtle` misses "mock-turtle" because the text has a hyphen where the pattern has a space, so the strings differ. The boundary rule plays no part in that. The case the rule actually covers is a string that sits next to a hyphen. Fix: "The string `turtle` also misses 'mock-turtle', because a hyphen next to a match counts as part of the word."
2. **The tip's account of `file:` and a moved claim.** Line 390: "Put a `file` on every entry. The press can then report a moved claim by name, instead of a missing one". The file: with no `file:`, a claim must match exactly once across the book. A claim whose sentence moves verbatim to another chapter still matches once, so it raises no fault at all, neither "missing" nor "moved". The `moved` fault exists only for a declared file ("is no longer in <file> but appears in <where>; update file:"). A claim that is gone from the book is "missing" either way. Fix: "Put a `file` on every entry. The press then notices when a claim leaves its chapter, and a common phrase in another chapter cannot make the entry ambiguous."

No claim in the chapter repeats an item on the section 20 list. The chapter follows the code on 20.A.6 (locators, not page numbers), 20.A.7 (the index sorts before authored appendices), and 20.A.5 (the cap is "per profile, 6.3 inches on the house 6 by 9 profile").
