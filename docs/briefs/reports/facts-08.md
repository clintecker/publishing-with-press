# Fact check: Chapter 8, Verifying the artifacts

I checked `book/chapters/08-verifying-the-artifacts.md` against `docs/briefs/facts/facts-08.md`. That covers sections 6.1 to 6.3, 6.6, 6.7, 5.3, and 2.3, the Shared context (1.4, 19, 20), and the managing editor's supplement (S1, S2: real `press verify` and `press verify-formats` runs on the Alice example, exit 0). Line numbers refer to the chapter. Slug: the captures use `alice-in-wonderland` and the book uses `alice`. Every fix below makes that substitution and nothing else.

**Captured output.** The chapter has one true capture, Example 8.4 (`press doctor`). Its lines match the file's 2.3 capture character for character, and the elisions are marked with `...`, but the chapter adds a prompt line that the capture does not have (Drifted 4). Every other code block is a message template. I compared each template with the file. The wording matches in all of them, including both detector messages, the four pdfinfo messages, the three link messages, the three ink messages, both print-profile messages, the cover messages, the witness messages, the EPUB metadata messages, the site messages, the epubcheck messages, the secret patterns, the head-leak pattern, and the agreement message. Some are broken across lines without the chapter saying so (Drifted 3). Examples 8.1 and 8.2 show templates where S1 and S2 now give the real lines (Drifted 1 and 2).

## 1. Unsupported

1. **The Alice example's sentinels, page floor, and title.** Lines 104 to 111: "The Alice example declares two sentinels, which Chapter 3 set with `press config set`", followed by `"Twinkle, twinkle, little bat"`, `"she made some tarts"`, and `verify-min-pages: 24`. Line 113 gives `ALICE'S ADVENTURES IN WONDERLAND`, and Figure 8.3's directive and alt text repeat the first phrase. I searched for Alice, Twinkle, tarts, sentinel, and title. The file supports only "2 sentinel(s)" (S1, S2) and the slug. It gives neither the phrases nor the title. S2 also casts doubt on the phrases. The book stitches "4 files" with "4 chapter witnesses", and its manuscript witness is "and here alice began to get rather sleep...", which is Carroll's first chapter. In Carroll, "Twinkle, twinkle, little bat" is in chapter 7 and the tarts are in chapters 8 to 12. A four-chapter excerpt may hold neither phrase. The page floor is contradicted outright (Contradicted 1). Fix: have the editor read the example's real `config/metadata.yaml` and print what it says. Otherwise recast the block as an illustration ("a book might declare") and say only what the file says: "The Alice example declares 2 sentinels."
2. **"the variable that CI sets when it builds a release tag."** Line 78. I searched for PRESS_RELEASE, release, CI, and tag. The file says only "a release build (PRESS_RELEASE=1)" and "Release witnesses under `PRESS_RELEASE`". Nothing in it says who sets the variable or when. Fix: "the variable that marks a release build (`PRESS_RELEASE=1`)". On the same line, "Chapter 3 ... calls these vacuous witnesses and shows the refusal" cannot be checked from this file. The editor should confirm it against Chapter 3.
3. **Embellishments on the 11.5 percent story.** Line 26: "The tests ran the generator, and the generator returned without an error. Nobody looked at page 1 of the PDF, where the cover was missing on one book and cut off on another." The file (war story 20) says only that the generator "shipped a dropped and a clipped cover at 11.5% coverage: the lines ran, the artifact was never inspected." It says nothing of two books, of page 1, or of errors. Fix: "The lines ran, but nobody inspected the artifact: one cover was dropped and one was clipped."
4. **Messages that "always point at the machine."** Line 89: "Both say that the machine that runs the verifier has a fault." Line 439: "A few messages always point at the machine: `required verification tool missing:`, `could not parse pdfinfo output`, both blank-page detector messages, and `epubcheck is present but cannot run`." The file gives a cause for only two of these. A missing tool is a toolchain fault, and the unrunnable epubcheck "the toolchain image is broken". It gives no cause for the detector messages or for a pdfinfo parse failure, and a malformed PDF could produce the second. Fix: line 89, "Neither message concerns your book: the verifier failed its own test." Line 439: drop "always", and drop `could not parse pdfinfo output` from the list or hedge it ("can also mean a damaged PDF").
5. **"A blank page in the output is the first sign of that fault."** Line 152, in the warning. The scar says a tall figure "makes LuaLaTeX ship empty pages forever, silently, at 100% CPU". In that fault the build hangs and never finishes. The file does not say that the fault ever produces a finished PDF with a blank page in it. 6. **"the same tools a printer or a retailer would use."** Line 30. The file supports this for epubcheck only ("the tool retail channels run"). Nothing says printers use poppler or pypdf. Fix: "The verifiers do their reading with outside tools: poppler's ..., the pypdf library, and epubcheck, the tool retail channels run."
7. **"No workstation sets that variable by accident, because only the image sets it."** Line 296. The file says `PRESS_TOOLCHAIN` is "set in the image". It does not say that nothing else sets it. Fix: "The toolchain image sets it. An ordinary workstation does not."
8. **"and the sentinel list starts empty."** Line 387. I searched for sentinel, template, and scaffold. The file gives the scaffold value only for min-pages ("the scaffold template writes 1"). Fix: cut the clause.

The Pages deploy serves `dist/pages`, a different artifact (5.3), and the file does not say that it holds `dist/site/` unchanged. 10. **"read every message" and "names the missing chapter outright."** Line 465: "which the agreement check in `press verify-formats` will usually confirm by naming the same chapter." ## 2. Contradicted

1. **The Alice page floor against the Alice page count.** Line 110 gives `verify-min-pages: 24`. Line 387: "The Alice example meets both rules with the settings shown". S1 (exit 0): `Verified alice-in-wonderland.pdf: 23 pages, ...`. The pdfinfo check fails with `suspiciously short PDF: N pages (minimum M)` when the count is below the floor. A 23-page PDF with a floor of 24 cannot pass, and it passed. So the example's floor is 23 or lower, which means it does *not* meet the release rule ("a release needs at least 24", 6.6). Fix: print the example's real `verify-min-pages`. Cut "The Alice example meets both rules". If the editor wants a release-ready illustration, say plainly that a 23-page excerpt sits below the release floor of 24, and that `PRESS_RELEASE=1` would refuse a floor set under it.
2. **"Every verify target builds what it reads before it reads it."** Line 408. The file, 5.3: `press verify-formats` "does not rebuild the PDF, but it reads an existing `dist/<slug>.pdf` into the cross-edition agreement check". 20.B.11 lists this as a bug-like behaviour. Line 415 describes the exception, but line 408 states the rule without one. Fix: "Every verify target builds the artifacts it verifies before it verifies them. One edge, described below, reads a file it did not build."
3. **The `press all` tip.** Line 418: "It is the one target that rebuilds every edition and runs every verifier over the results". The file: "**`press all` does not build `print` or `coverwrap`.**" Its verifiers are `verify_pages`, `verify_pdf`, `verify_formats`, and `verify_archives`. It does not run `verify_coverwrap` or the print profile. Line 425 itself says so. Fix: "It rebuilds every reading edition, the source zip, and the Pages site, and runs `verify_pages`, `verify_pdf`, `verify_formats`, and `verify_archives` over them. For the print pack, run `press verify-print` as well."
4. **"Every verifier message names its subject in its first words."** Line 437. Many of the file's own messages do not, among them `required verification tool missing:`, `suspiciously short PDF`, `missing text sentinel in PDF`, `apparently blank rendered pages`, `ink touches rendered page edge`, `rendered N pages, pdfinfo reports M`, `assets/cover.jpg exists but page 1 ...`, `missing or suspicious artifact:`, `no manuscript witness derivable;`, `docx embeds N images`, `reader site is missing`, `dead fragment`, `broken reference`, and `sources companion looks empty of entries`. Several of these also appear in Table 8.7, which puts the chapter at odds with itself. Fix: "Most verifier messages name their subject early", with Table 8.7 (or a new column in it) mapping each message to its verifier.
5. **"run `press doctor`, which checks each tool the verifiers need."** Line 439. 20.B.14: "Doctor does not check `pdfimages`, and its absence silently softens two checks to notes." Fix: "which checks the tools the verifiers need, except `pdfimages`. Check that one yourself (line 190's tip)."
